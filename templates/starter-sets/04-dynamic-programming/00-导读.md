# 先让状态足够，再让依赖有序

动态规划不是看到题就套一个二维表。[[01-状态与信息是否足够|状态]] 要说明哪些历史已经可以忘掉，[[02-例题-最少硬币与边界|硬币例题]] 再把一句状态含义写成转移、边界与计算顺序。它同时给出一个贪心失败的反例：局部选得大，不一定全局用得少。

[[03-最优子结构与反证|最优子结构]] 解释为什么能把最优解的一部分换成子问题最优解，前提是换完仍合法。[[04-记忆化与自底向上|记忆化]] 说明缓存减少重复求值，却不能修复错误状态或循环依赖。把依赖画出来后，[[05-例题-DAG上的最优路径|DAG 例题]] 会让计算顺序变得具体。

最优数值不等于最优方案。[[06-路径还原与前驱语义|路径还原]] 记录选择从哪里来，也提醒覆盖表格后前驱可能失去原有语义。这个问题在空间压缩时尤其重要。

接着并排读 [[07-例题-零一背包的倒序|0/1 背包]] 和 [[08-例题-完全背包的正序|完全背包]]：两者看起来都在更新 `dp[j-w]+v`，但读取的究竟是上一层还是本层，决定同一物品能否再次使用。顺序在表达问题，不是小优化。

最后用 [[09-例题-LCS与子序列|LCS]] 处理两个前缀，再用 [[10-例题-矩阵链区间DP|矩阵链]] 处理区间拆分。每次先说状态和依赖，再估计状态数乘每态转移数；不把所有 DP 都记为一个复杂度。[[白板/章节.canvas|白板]] 只练部分决策，完整题目与可核对例子仍在卡上。

## 阅读步骤

## 节点一：状态留下的信息够不够

核心问题：未来计算究竟需要保留哪些过去的信息？硬币例题让状态、边界与顺序落到具体输入上。

教学目标：说明状态含义及必要信息，写出可核对的转移与边界，不由局部直觉直接认定全局正确。

- [ ] [[01-状态与信息是否足够|状态]]：说明状态保留哪些必要信息。
- [ ] [[02-例题-最少硬币与边界|硬币例题]]：写出转移、边界与计算顺序。

### 本节足迹

## 节点二：子问题的答案何时可以复用

核心问题：什么时候能复用子问题答案，又该按什么次序计算？状态确定后，继续检查替换的合法性与依赖关系。

教学目标：解释最优子结构的依据，检查依赖是否允许当前求值顺序，并用具体例子核对。

- [ ] [[03-最优子结构与反证|最优子结构]]：检查替换子问题最优解后是否仍合法。
- [ ] [[04-记忆化与自底向上|记忆化]]：比较缓存与有序计算的条件。
- [ ] [[05-例题-DAG上的最优路径|DAG 例题]]：按依赖关系确定计算次序。

### 本节足迹

## 节点三：最优数值之外，怎样找回选择

核心问题：有了最优数值，怎样找回一个合法方案？需要检查每次记录代表哪一步选择。

教学目标：说明前驱语义并检查还原过程，区分算对数值与得到合法方案，不把后者视作自动成立。

- [ ] [[06-路径还原与前驱语义|路径还原]]：说明前驱记录代表哪一次选择。

### 本节足迹

## 节点四：表面相近的转移为何需要不同顺序

核心问题：相近的转移式，为什么可能需要不同的更新顺序？背包、前缀与区间的状态语义和依赖会变化，先比较条件，再决定能否复用旧写法。

教学目标：追踪更新前后读取的状态，解释计算顺序与合法选择的关系，并分别估计状态数和转移成本；小例子通过不代替一般证明。

- [ ] [[07-例题-零一背包的倒序|0/1 背包]]：解释倒序为什么避免重复选取。
- [ ] [[08-例题-完全背包的正序|完全背包]]：与零一背包对比，解释正序的含义。
- [ ] [[09-例题-LCS与子序列|LCS]]：明确两个前缀的状态与转移。
- [ ] [[10-例题-矩阵链区间DP|矩阵链]]：说明区间拆分与计算复杂度。

### 本节足迹
