# 整书骨架与批量整理

沿用 `notara-pdf-learning-set` 的文件与关系合同。这份参考用于整书、多书比较和批量续拆；只交来一个问题时不启动整套流程。

## 先确定骨架和标杆，再扩展

先读各书目录、导言、章节起止、代表正文与答案布局，比较作者围绕什么问题推进、哪些材料擅长解释、哪些擅长练习或综合。记录书名版本、PDF 物理页与印刷页对应；偏移变化分段记，不把目录略读写成全书细读。公式、图形与扫描页按实际页图核对，文字提取只作定位辅助。

结合约定目标列本批原子实体、直接前序、横向联系及代表例子。跨书按对象、条件、结论和用途对齐，名称相同不直接合并；同一知识补充不同来源。原书章节导航与知识骨架分开，保留各书路线的差异，不强造统一大桶。

主会话先精写一组原子主干卡和一个有代表性的具体例子作为标杆，核对粒度、解析深度、来源及实际关系。样本应触及本批的真实难点，如跨页题面、图表或方法分岔。用户已给明确标准或批准过同类样卡时沿用，不额外加确认停顿。范围含全部例题就继续完成全部；范围只要骨架就选择能体现条件、方法差异和递进的例子。

## 按依赖分工，不复制整段上下文

- 主会话负责骨架、跨书对齐、标杆、取舍和正式保存；内部工作员返回完整草案与证据。独立页段可并行，依赖未定稿实体或上批结论的工作串行；子任务不能再次委派。
- 原生 `subagent` 使用当前工具 schema。用 `worker-general` 查资料与起草，推导或计算可交 `worker-problem`，原页与逻辑风险核验交 `worker-review`；沿用当前模型配置，不在提示词中发明模型参数、切换供应商或假定低价模型已安装。此分工用于材料整理，不覆盖主老师、调研、审核的既有整课备课分工。
- 每个交接单给：本批页段/题号与原件定位、已读的实体路径清单、标杆文件、任务目标、原书答案位置、不可改动的已有记录，以及需要返回的草案和疑点。工作员先加载本 Skill 及所需参考；不复制整书、全部课堂历史或无关学情。
- 批次以能完整核对和交付为尺度，按章节、页段或独立主题分，不固定题数。需要本轮统稿就前台等待完整结果；后台启动仅是回执，等原生完成通知后再整合，不把未返回任务报为已完成。

## 脚本做机械核对，模型判断内容

可用脚本承担页数/目录清点、YAML 解析、文件目标存在性、题号清单和重复文件检查，减少模型逐行做机械比对。整理会话没有 `bash`，将此类只读核对交给已有脚本权限的 `worker-review`；当前老师有权限时也可直接检查。工作员的脚本仍不修改学习资料。

核对范围明确区分本批新增参考卡、本批修改的旧卡和原封不动的历史资料。仅本批纯来源新卡要求学生理解为空且不生成复习记录；旧卡保留真实学生理解与历史排期，模板占位也不当作正式材料错误。关系检查以当前 Notara 解析器为准，不能用字符串计数替代前序分组、标签身份和来源定位。现有执行环境没有某项检查能力就如实注明，不擅自安装依赖或声称通过。

脚本结果列出实际检查项、错误和提示：公式分隔符闭合不代表公式正确，文件存在不代表页码正确，成功退出不代表无提示或数学已核实。主会话核验原页、标杆和跨书关系；核验员重点看疑点、代表题、综合题及原书勘误，检查定义域、同一比较范围、等价变形和边界。按材料风险抽检，不把抽样写成逐题审阅，也不让格式偏好挡住已可用材料。

## 分批交付，能够接着做

每批由主会话保存并回读，检查卡片类型、摘要、完整题面、图表、来源与实体引用。新增关系使用已有直接前序与横向语法，不因图面拥挤删除真实关系；例子挂接按最贴切实体与真实独立分支，不凑固定条数。

原书导航用 source/guide；横向专题说明同一问题在不同章节如何出现，但不在学生题目导航里提前写出解法或勘误答案。按需求提供通用路线建议，说明选材及递进，可用本 Skill 的 `templates/route.md` 起草；通用路线不冒充个人已学进度。正式长期路线仍由负责续接的首页教师或当前老师维护，整理会话交还建议草案，不改学生个人路线。制作学习集不默认逐课备课。

沿现有整理日记维护本次范围、已略读/细读页段、新增/补充的文件、已核对关系、未处理与存疑项、下一批续接点；用真实文件定位续做，不另建任务系统，也不凭口头总结整批重做。改名或重组先核对引用与学生记录，不让工作员直接删旧卡。交付与日记通知仍走原 Skill 的既有收口路径。
