# 学习记录与续接

课堂、零碎问答、错题、阅读、编程调试或实验探索中，出现值得保留的认识、疑问、纠错或方法时使用。不必等整节课结束，不要求先答对一道题；没有新变化不为记载而记载。学生明确不保存或限制范围时遵守。

## 1. 写到哪里、怎样保留具体帮助

先读相关记录去重，保留这次具体做了什么、关键帮助与认识变化，不给整张卡笼统评等级。按系统提示词中的“学习记录”说明区分首次实质提出、提问搭梯和讲解后验证，把接力完成的步骤分别写清（例如“老师问谁的和固定后，学生选出两项，随后自己完成计算并主动核对取等”，既不缩成“独立解出整题”，也不抹掉后两步的进步）。来源归属不等于现在的能力：以前由老师教过的方法，今天无提示运用仍是本次独立应用。

- **有对应卡片时复用卡片**：教师解释与其他方法归 `## 参考理解`；学生实际表达、问题与理解变化归 `## 学生理解`，值得以后回顾或延伸的问题放在唯一的 `### 下次探讨` 下（已解决或撤回的问题同步勾选或移出当前探讨，原过程保留）。学生真实表达的卡片间联系按 `notara-pdf-learning-set` 与卡片模板写入 `### 已建立的联系`，不因一次记录点亮全部知识标签。
- **没有合适卡片时写日记小节**：写入 `type: diary` 日记的独立、唯一标题小节，标明实际主题；不为了记一次学习强行新建卡片。已有日记小节可原位补充，普通认识记录无需填结果和帮助枚举。
- **保存后回读**：使用 `read`/`write`/`edit` 保存并 `read` 回读。原话与概括、事实与推测分开；纠偏时更新冲突的当前判断，保留可回查的原话、提示过程和纠错依据，不硬截断。

## 2. 设计“下次可以继续”并酌情排时间

可以只留下一条认识而不排期。确有值得再来的内容时，围绕已有 `### 下次探讨` 或本次卡点设计一个**具体问题或动作**（回忆、补缺、迁移、比较或拓展均可；老师推荐的问题不记成学生主动发现）。

结合本次表现、帮助经过、既往遗忘情况、目标与近期时间，自主判断几天后回来（`afterDays`，非负整数，`0` 表示今天）并写明简短依据（`reason`）：理解稳定可晚些，关键入口刚靠提示走通可明天再试，真正缺前置就先补缺口；**不套 1/3/7/16/35 固定梯度，不按累计次数升级**。探索也可接在下一节相关课，不把没做独立测验写成欠缺。

先保存真实学习经过，再按 `learning_followup` 工具说明执行 `read` → `plan`（或无需再回访时 `clear`）：

```json
{"action":"plan","path":"卡片/比较两项.md","expectedRevision":"使用刚才read返回的revision","question":"换一个条件，自己找出该比较的两项，并解释理由。","afterDays":3,"reason":"后续运算已走通，选比较对象仍借助提示。"}
```

以工具回执中的安排为唯一当前排期，不再手写旧 `next_review/mastery/interval/learned/last_review` 字段，也不在正文重复抄写日期；版本冲突时先重读核对新内容再决定是否改期。

## 3. 正式检验确认的完整格式（`notara-review` 渲染围栏）

`notara-review` 是对话渲染格式，不是工具调用。仅在**实际检验了某张卡片或日记主题的关键步、适合留正式检验记录**时在回复顶层输出；普通探索讨论不强制生成确认卡，里程碑检验也不自动变成正式复习确认。

- **前置枚举提示清单（先写 `note` 中的 `提示清单`，再填 `support`）**：输出 `notara-review` 围栏时，先在 `note` 开头如实列出本次给过的所有关键步提示（含是否提供了 `flow` 留白或其他拆步组件、中途点拨或刚讲完同类示范；若全程无任何提示与拆步框则写 `提示清单：无`），在 `note` 中保留必要提问与经过，避免把“本次独立应用”写成“首次发现”：

```notara-review
{"targetPath":"卡片/xxx.md","keyStep":"本次检验的关键判断或步骤","note":"提示清单：<列出本次给过的具体提示或拆步框，无则写“无”>；作答表现：...","result":"done","support":"hint"}
```

- **复习事实、帮助经历与排期分开**：
  - `result` 只反映这一步本次表现：`done` | `missed` | `unchecked`；
  - `support` 只写这一步本次帮助经历：`independent`（无提示）、`hint`（有提示）、`explanation`（看过讲解）、`unknown`（不确定）。无提示但未完成可以是 `missed + independent`；看过讲解尚未检验可以是 `unchecked + explanation`。日记记录另填唯一 `heading`。
  - 围栏可附可选 `followUp:{"question":"...","afterDays":3,"reason":"..."}` 随记录供学生一并确认（省略则保留原安排，`null` 则清除该项）。
  - 模型输出仅作建议，最终帮助条件与结果须由学生明确选择确认；确认后回读真实回执，确认结果不会自动按档位升级排期。仅查看或调整排期时优先用 `learning_followup`，不再制造一次学习结果。

## 4. 收口与交回长期教师

阶段任务真正收口后，在日记报告或课稿总结节写清实际认识变化、必要帮助、卡片定位和已保存的续接安排，`read` 回读后沿 `lesson_summary` 交付。有首页绑定时，长期教师结合整体路线和其他任务统筹画像与路线（不重写没有变化的画像，需要改期时用 `learning_followup` `read`/`plan`）；普通等待与 idle 不是收尾，不自动唤醒新回合。内部工作员和同学只交真实依据或建议，由有写权限的老师保存；整理员只保存资料和清单，纯导入、备课不制造学生表现或复习安排。关系写法仍沿 `notara-pdf-learning-set` 与卡片模板，不因一次记录点亮全部知识标签。
