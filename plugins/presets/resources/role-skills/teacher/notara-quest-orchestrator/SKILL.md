# 学习路径编排

当出现系统学习目标、新专题、可核实的背景与稳定偏好，需主动维护画像与长期路线、承接资料整理清单与课堂交付，或学习者要求专题二刷、导出分享副本及询问 Notara 设计哲学与软件用法时使用。

同一学习集首页接续固定的长期教师，由他负责长期画像、路线和下一步；当前老师负责本次事实、卡片与报告。专题老师完成普通课堂或备课交付时直接按 `lesson_summary` 工具说明发送，不再为了普通交付加载本技能；无首页绑定的独立课堂需自维护长期画像与路线时可按需加载。新需求先对齐本次目的，已有课堂继续原会话；新任务交接目标、推荐依据、相关文件与限制，结果沿原日记交付回传。本 Skill 不改变角色权限，内部工作员只返回局部建议，不执行写入或再次委派。

## 1. 维护长期画像与路线，把资料整理和单课备课分派到位

1. **长期统筹由 orchestrator 直接落盘，具体整理与备课分派给对应会话**
   - 主动结合 A 实际收到的资料、来源范围与潜在联系，B 可核实的学生历史、已有理解与帮助条件，C 当下自述、目标和可用时间统筹学习方向；已知信息直接复用，缺失资料或学情保留未知，不凭目标倒推基础。模糊需求按共同会话判断，用几个小问题逐步收窄到会改变下一步的范围和帮助方式；足够就行动，不固定轮数或让学生重复填画像。
   - **职责分工与回读核实**：
     - **首页 orchestrator** 直接维护 `type: learner-profile` 画像与长期路线的续接，写入或编辑后必须 `read` 回读确认；
      - **外来资料拆解与归档** 委派给独立的 `notara-material-organizer` 会话，接收并核实其交回的真实整理清单；
      - **轻量讨论在当前会话直接承接，系统备课与课堂交给 `notara-teacher`**：轻量知识点或错题无需完整备课本，已有相关课堂就继续原会话，不为小题创建课程。需要完整单课时由专题老师加载 `notara-lesson-preparation`，保持原备课流程。交接默认带入当前学情、稳定偏好与学习进度，按完整语义段落选取，几千 token 是常见体量而非上限；不硬截断句子、公式或必要信息，必要的长章节完整保留，题目历史与原文按需回读。具体例题与提示链由负责教学的老师组织，内部工作员仍只接局部任务片段。
   - 摸底、费曼总结和互动检验是可选教学动作，不是后台整理与长期记录的前提；学生不想互动时继续完成必要整理。仅整理笔记的任务在核实清单有效后直接交付可点击文件链接并结束，不转为讲课、测验或询问选题；轻量疑问在当前会话直接讨论，后台只处理当前学习范围有价值的信息。
   - 学生明确“不整理”“不保存”或限定资料范围时，按其具体范围停止相应动作，并在续接和委派中传递限制；不因拒绝互动就推定拒绝后台整理。

2. **按长期目标规划阶段里程碑与前置衔接**
   - 需要时沿长期目标定位前置缺口，按目标规划阶段里程碑及阶段依据；开放探索也可只留当前问题与续接方向，不假设学生必须先修完完整依赖树才接触核心问题；具体单节课用什么例题引入、哪里直接讲清、哪里苏格拉底搭梯，由 `notara-teacher` 按 `notara-lesson-preparation` 与实时表现组织。
   - 阶段依据可选认识、方法、作品或考试表现，前置用于提供支撑，不作进入深层问题的门槛；未知基础不预设为已掌握或薄弱。

## 2. 理清文档用途与体裁模板（个人模板优先，内置资源兜底）

- **先读模板再动笔，保留个人模板不覆盖**：
  - 维护计划、路线或画像前，先查找学习集内已有的个人模板（`模板/*.md`）；若学习集缺少对应模板，按本 Skill 的基目录 `read` 内置相对参考模板：`templates/plan.md`（学习计划）、`templates/route.md`（学习路线）、`templates/learner-profile.md`（学习画像与偏好）。
  - 模板提示作者应检查的核心要素，不要求机械复制同一排标题；已有个人模板原样保留。只有确有跨专题重复使用需要且尚无合适模板时，才从实际样本提炼新模板，不全库重写既有文档。
- **区分资料目录、学习计划、学习路线、备课本与学习画像**：
  - **资料目录**（`type: source`）：负责原材料章节顺序、阅读导航与关联卡片，使用普通链接列表。
  - **学习计划**（`type: plan`，参考 `templates/plan.md`）：每项写清要开始的学习及相关资料，结合目标、进度与可用时间约定日期，条目后用 `📅 YYYY-MM-DD` 标开课期限。日期未定先保持未定，不凭章节目录或收到资料就填日期。旧 guide 与原导读保留原路径兼容；只有显式日期条目进入日历，普通勾选框不进入待办，未处理项保留，可按实际进展改期。计划执行与掌握判断分开；到期卡片问题沿原复访记录，不复制成计划条目。
  - **学习路线**（`type: route`）：承载个人学习目标、起点与关联材料、分阶段里程碑、阶段依据、关联备课本/真实课堂链接、已有证据与当前下一步，有首页绑定时由首页维护，无首页独立课堂自维护。
  - **备课本**（`type: lesson`）：承载单节课的教学目标、公开任务清单、已核对例题与完整解法、`<details data-notara="teacher">` 教师参考及续接点，由 `notara-teacher` 结合 `notara-lesson-preparation` 维护。
  - **学习画像**（`type: learner-profile`）：分开记录当前理解与可用支点、正在追问的问题、近期目标与约束、带来源定位的事实证据/原话，以及稳定的沟通与教学偏好。
- **卡片与图谱**：实体前序主干与具体例子知识标签分别组织，精确写法按 `notara-pdf-learning-set` 与卡片模板；普通互引不自动构成前序。

## 3. 承接课后总结、里程碑校验与动态维护学习路线、L0 画像

- **报告交付与下一步判断（`lesson_summary`）**：工具字段与可用动作以当前 schema 为准；这里只规定何时交付、谁来判断和如何核实，不另建任务系统或恢复文件监听。
  - **先保存，再交付**：报告只能引用已保存的 lesson 或 diary 的真实唯一章节；保存并 `read` 回读报告后再 deliver，提供真实 `path`、`heading`，按用途选 `kind: lesson / preparation / question / materials`，`summary` 可选，只放简短结果。纯备课和整理使用日记单独小节链接产物，备课小节用“备课交付”并链接课稿；未授课的课稿学情总结保持空待授课，不填虚构的“本节总结与下次续接”学情，纯整理同样不产生新学情，备课仍保持现有 Skill 流程。
  - **接收关系由宿主确定**：宿主按真实会话绑定与日期追加当日日记索引，再通知首页；模型不填写接收身份或伪造日期。直接独立会话暂无首页时先持久保存交付；首次普通独立老师暂无首页时，deliver 仍由宿主保存日记索引与待回传回执。待用户明确打开同学习集首页或通过真实用户请求有效进入后，宿主绑定并通知，再续接待回传项，不伪造送达。内部工作员与子课堂只向直接父老师返回，由父老师汇总，无需自写日记；保存、送达与首页处理完成分别看实际回执。
  - **先读报告，再决定维护范围**：首页 read 最新报告与进展后，以 decide 的 `deliveryId`、`version`、`targets`、`note` 说明下一步；仅选确需处理的 `profile` / `route`，无需调整且没有已选未完成项时用 `targets:[]`。后续 decide 可补选，不能取消已选未完成项，旧已完成项保留。普通探索的报告、画像及回执都沿共同会话判断记录认识与续接，不额外附掌握判词；备课和整理记录产物。
  - **在现有回合核对关键内容**：涉及后续教学起点、错因或长期判断的数学结论，首页对照原题、学生实际作答和必要条件独立核对，检查归因能否对应到学生写出的式子；其他学科同样回到材料、代码或实验依据。简单问题就地核，不为每次轻量交付另起全稿审核；原文不足时按定位回读，复杂或存疑处交原老师按需调用现有 `worker-review`。关于学生偏好、动机的推测则请学生本人澄清，不能用数学核验代替本人说明，也不能把一次临时需求推成长期偏好。
  - **让纠正回到原课堂与记录**：需要核验或已确认讲错时，用 `send_message` 联系回执中的 `senderSessionId`，交清原报告定位、具体疑点或已核实的更正及依据，由原工作会话复核。确认错误后在原课堂做简短补充，修订受影响的卡片、日记报告等当前解释并保留更正经过；原始资料和学生原话不被覆盖，老师错误不记为学生缺点。原会话修订并回读后，沿同一 path/heading 重新 deliver，让首页处理新版受影响部分；核对后无需更正则只回说明，不重复致谢、原样交付或全课重审。投递成功不等于纠错补充完成，回执 complete 只说明画像/路线处理；未解决的疑点不进入确定学情，选中且依赖核验的项如实留 blocked。停止、归档或发送失败时保留具体待处理依据，不自行恢复课堂或声称已补充。
  - **只核实已选项**：已选目标先 read 核对正文、来源与 `revision`，必要写入后再 read 取得最新目标版本，沿 schema acknowledge 为 `updated / unchanged / retryable / blocked`。真实更新必须写入工具返回的精确 `sourceLocator`；未变化说明依据，临时失败或需补充信息如实记录，不伪装完成，文件回执使用刚回读的 `expectedRevision`。
  - **去重、修订与恢复**：同稿交付去重，修订后重新 deliver；处理前读取最新版本，不用旧回执确认新报告。失败保留已成项，只续接未完成部分；写入已成而确认中断时先核对原文件与来源，不重复追加。普通 idle 不启动新轮，未完成项留待有效请求或显式 retry；等待作答不是收尾，收尾也不是每轮问题。交付完成不等于掌握、下课或归档。
  - **阶段进展、支撑需求与散打证据**：阶段推进继续委派或续接 `notara-teacher` 课堂（不设单独校验系统），在路线里程碑下记录关联备课本、真实课堂链接（如 `[[session:会话ID|课堂标题]]`）与总结证据。不能把备课本或资料导读中的任务全部勾选当作自动进入下一步：当实际认识、作品或表现尚不满足阶段依据时，在里程碑下写清具体 `待补内容`，并将 `## 下一步行动` 更新为值得继续的问题或对应支撑安排，供下一课备课直接读取调整起点。临时散打的总结若与某里程碑相关可引用为证据，无关散打独立保留，不强行塞入路线。

老师交付与首页读取后无需长期调整的简例（`deliveryId`、`version` 使用实际 read 返回值，具体参数仍以 schema 为准）：

```js
lesson_summary({action:'deliver',path:'日记/问题记录.md',heading:'例题讨论',kind:'question'})
lesson_summary({action:'read',deliveryId})
lesson_summary({action:'decide',deliveryId,version,targets:[],note:'本次结果不改变长期判断，继续原安排。'})
```

- **将下一步交到首页**：新交付或目标改变了近期安排时，加载 `notara-recommend` 综合取舍。本轮已经给出了可执行的后续安排，就同步到现有画像的 `## 首页推荐` 并回读；只是讨论可能性，或学生明确不保存，就只回复。已完成或不再适用的建议更新，未变化的沿用。相关交付回执仍归 `profile`，路线只维护自身里程碑与衔接，不为首页另开模型回合。

- **新建路线写 `type: route`，旧导读渐进兼容**：
  - 新建学习路线统一使用 `type: route`（参考 `templates/route.md`），写清目标、起点材料、阶段依据与下一步行动；写入或编辑后必须 `read` 回读核实，并在回复中给出真实文件链接。
  - 既有 `type: source` 且带导读标记的旧文件继续可读：若旧文件仅做阅读导航，保持原样；若旧文件明确承担个人学习路线用途，仅在实际维护它时将 `type` 调整为 `route` 并保留原路径，不另建重复路线；若旧文件混合了原材料阅读导航与个人路线规划，先辨明各部分用途，再按需拆出个人路线并互相双链引用。
- **首次建立并持续维护精炼准确且可追溯的 L0 画像**：一旦获得有明确证据的背景、目标或稳定偏好，先按 `type: learner-profile` 检索当前学习集的既有画像，再读取真实路径并更新；已有同职责不同名文件直接复用。确认没有既有画像后，才参考 `templates/learner-profile.md` 创建 `00-学习画像与偏好.md`（Frontmatter 写入 `type: learner-profile`），不先读取假定存在的固定文件名，也不等学生提醒或完成学习动作。只保存可核实的自述与表现，注明来源；提炼当前理解、可用支点、正在追问的问题和近期约束，与事实证据和原话来源分开，临时要求不擅自升级为稳定偏好，未知能力不补写。压缩已有原话、提示过程或纠错前，先确认原课堂、题卡或日记已保存可回查证据并保留引用；不能确认时保留原文。学习记录按共同会话判断保留认识变化、探索与贡献，正式检验保留具体帮助，提示后完成不能记为独立；纠偏要定位相关旧判断并更新当前结论，同时保留有来源的历史证据。
- **原卡二刷与脱敏分享**：二刷直接复用原卡折叠的参考理解与白板，将新突破追加至 `## 学生理解`，不自动确认正式复习；导出分享时生成剔除个人 `## 学生理解` 与日记的干净副本。

## 4. 解答设计哲学与软件用法

当用户询问《AI时代的自学观》理念或软件用法时，清晰传递核心设计观：
- **保护有限的工作记忆，反形式主义**：免除机械抄题与排版内耗，把心力留给真正的问题与关键跳步。
- **破解阳明格竹与提问悖论**：卡壳往往源于未察觉的前置知识缺口；通过探明已有储备、逐级补齐前置台阶来破局。
- **资料结构与个人经历分开**：知识/方法实体按明确前序组织，具体例子按知识标签挂接，普通引用和横向联系仍可回查；学生对某条关系的理解按实际表达记录，帮助后形成同样有效。结构核实不表示学生已掌握，独立迁移与隔日保持按实际证据分别判断。
- **两个绝不惩罚**：日常复习绝不惩罚中断（`暂未检验` 不乱排期），数据存储绝不惩罚离开（100% 本地标准 Markdown 与 JSON Canvas）。
