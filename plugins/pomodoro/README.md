# 课堂番茄钟

独立插件 `@oh-my-student/plugin-pomodoro`，使用已安装 DSH `0.2.1-rc.4` 的 `schedule`。侧栏时钟启动当前主课堂的提醒：默认45分钟，每10分钟一次，末次45分钟收尾。时长/间隔可调整，每节最多12个提醒。

Host 只有 `status/start/stop` 三个窄 RPC。主机生成有界的一次性调度，原生 Schedule 是唯一持久计时记录。页面关闭、切换会话、切换工作区不会改绑目标；不依赖浏览器 setInterval 投递，不创建新对话、不自动切页。UI 轮询只更新状态。

侧边栏不再提供独立番茄钟入口。启用 vault-views 后，在“活动 → 后台进程”的“课堂计时”中查看状态、设置或停止计时；通过 `notara.activity.timer` 槽绑定活动面板所属会话。侧边栏“插件”由 vault-views 提供，打开 DSH 原生插件管理，和番茄钟启停相互独立。

同一 Host 内串行 start 防止重复创建。原生调度负责冷恢复与持久收件箱投递，但会话 flush 和调度状态是两次写入，中间崩溃可能重复投递，不能承诺 exactly-once。停止只撤销当前观察到的批次中尚未投递的任务，已投递消息不删除。没有活动任务时状态返回 idle，不把上一批历史投递冒充本次结果。送达不代表模型已执行，更不代表学生完成学习。

稳定的版本化标记保存在同一原生 schedule prompt 首行，改名或修改后续提醒文案不影响识别；主动删除标记后需从原生自动化管理操作该任务。在完整 Notara 发行版的聊天投影中，标记和提醒输入不显示在学生聊天中，老师对节奏的正常回应仍可见，轨迹保留原始记录；这一展示保证依赖 bundle 文档所列的 rc.4 Chat 适配。提醒包含开始/计划节点/时区，老师按实际送达时间校正节奏。休眠或关闭 DSH 时不保证实时提醒，重启后可能收到逾期节点；每节的提醒数量有界。插件停用不撤销原生持久任务，请先停止计时或在原生自动化管理中删除。

仅主课堂可启动；原生服务拒绝委派 child。模型与学生身份、额度不由此插件管理。

检查：`node --test test/*.test.js`；在工作区运行 `node --test tests/pomodoro-integration.test.mjs`。浏览器用隔离副本和测试调度加速，不向真实课堂发消息。
