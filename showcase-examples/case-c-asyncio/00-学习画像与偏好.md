# 学习画像与偏好

## 我是谁与当前水平

- **学习目的类型**：实用技能实践（Python 异步并发编程与接口并发请求改造）。
- **当前水平梯度**：第一梯度（破冰起步期 $0 \rightarrow 1$）向第二梯度（独立破局期 $1 \rightarrow N$）过渡。
- **当前认知底座**：熟练掌握普通 Python 同步函数（`def`）、函数调用栈顺序执行逻辑、以及使用 `for` 循环配合 `requests.get()` 顺序请求接口与 `time.sleep()` 延时；但对 `asyncio` 中的事件循环（Event Loop）、协程对象（Coroutine）、任务（`Task`）、`await` 挂起机制与 `gather` 并发编排存在概念断层。
- **近期目标**：搞懂 `asyncio` 单线程协作式并发的心智模型，排查并修复“在 `async def` 中写 `time.sleep(1)` 和 `requests.get()` 跑 5 个任务仍耗时 5 秒”的假并发问题，掌握从同步串行代码迁移到异步并发与阻塞卸载的标准实现模式。

## 教学偏好

- **有效讲法**：新概念首次出现时，直接拿熟悉的普通 Python 同步函数调用栈和 `for` 循环做具体对比；先给最小可运行代码（MVP）和真实耗时输出，再拆解底层调度时间轴。
- **易烦雷区**：反感堆砌抽象并发黑话而缺乏代码对照，反感脱离真实运行耗时数据的空洞说教。
- **例子偏好**：偏好批量网络接口请求、I/O 等待耗时对比、可直接用 `python3` 运行验证的极简脚本。

## 学习习惯与常见卡点

- **实操习惯**：喜欢自己动手改写代码并实测运行耗时，通过观察终端输出验证是否真正并发。
- **常见卡点**：
  1. 容易把 `async def` 当作“自动开启多线程并发的装饰符”，误以为只要套上 `async def` 并在内部调用 `time.sleep(1)` 或 `requests.get()` 就会自动并发；
  2. 容易混淆“直接连续 `await` 两个协程对象”与“先 `create_task` 注册任务再 `await`”在调度时机上的差异。

## 积累

- **同步阻塞函数污染事件循环**：在 `async def` 内部直接调用 `time.sleep()` 或 `requests.get()` 会卡死事件循环所在的唯一主线程，必须替换为原生异步库（`asyncio.sleep` / `httpx.AsyncClient`）或用 `asyncio.to_thread()` 卸载到工作线程。
