## 参考理解
<!-- 填写说明（模板列出写卡时要注意的要素，按内容自然组织，不要求每张卡机械补齐同一排子标题）：
【1. 本类核心关注点（产生动机、条件与正反例）】
- 引入动机（旧工具何处不够用）：先对比已熟悉的同步代码或旧写法在面对当前问题（如高并发 I/O 等待）时的瓶颈，说明引入该语言特性的必要性；
- 定义拆解与关键限定词：区分容易混淆的语法实体（如“协程函数 async def”与“协程对象 coroutine object”），抠出拿掉就会报错或改变执行语义的前提条件；
- 底层运作与控制流转移机制：顺着执行时间轴，写清调用、挂起（suspend）、让出控制权、事件循环调度与恢复执行（resume）的完整状态流转；
- 正反例对比与失效边界：给出标准正例代码与典型误用反例（如只调用不 await、连续直接 await 导致退化为串行、混入 CPU 密集同步调用导致并发失效），划清适用边界。

【2. 高频漏检与防坑要素（审题与实操必查）】
- 必查对象生命周期与执行触发条件：调用函数究竟是“立即执行函数体”还是“仅返回待调度的冷对象”；
- 必查控制权让出条件：`await` 右侧的对象是否真正支持非阻塞挂起，主线程是否被同步调用锁死；
- 必查引用保持与异常传播：后台 `Task` 是否保留了强引用（防止被 GC 提前回收），取消异常 `CancelledError` 是否被意外吞掉。

【3. 白板与可视化推演建议（怎么摆白板）】
- 优先使用 `frames` 组件逐帧演示单线程事件循环中多个任务的状态流转与时间轴对比（运行中 Running / 挂起等待 Suspended / 就绪 Ready）；
- 配合 普通填空题挖空关键语法原语（如 `create_task`、`await`），或用 `flow` 画出从函数调用到事件循环调度的控制权移交路径。

【4. 需要建立的联系（双链方向）】
- 向上/同级关联：知识库中上下游的语言特性卡（如从 `await` 机制关联到 `Task` 并发调度）；
- 向下关联：知识库中调用该特性的共性模式卡（Recipe）与具体实战排错案例卡。

【5. 复习抽考关键步（Key Step）与变式方向（写在末尾 ### 下次探讨）】
- 抽考关键步：给定一段含两处异步调用的代码片段，无提示判断其总耗时是相加（串行）还是取最大值（并发），并说明事件循环在每一秒的控制权归属；
