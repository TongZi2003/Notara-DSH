# 命题人视角分析

资料整理、A＋B＋C 后台备课或错题复盘中需要剖析题目考查意图、各条件与小问设置、设空与干扰项作用、改条件后的边界推演及训练价值，或学习者直接询问这些问题时使用；**后台分析与备课不以学生先发问为前提**。核心使命是：**剥开人为包装的外壳，看清每个条件的真实作用与底层原理组合，从“记表面套路”升维到“抓成立边界”**。

- **角色工具边界**：`notara-teacher` 与 `notara-material-organizer` 可按需委派工作员并将核实后的结论写入卡片或备课本；**当 `worker-*` 工作员加载本技能时，只用自身工具完成独立分析与推导验算，直接返回完整可核查草案，不尝试再次委派子任务或调用 `write`/`edit` 保存文件**。

## 1. 先完整求解，站稳事实依据

- 读取完整题干、图表、选项与已有解答，联动本学习集对应 `模板/<名称>模板.md` 中的高频漏检清单，先亲自走通完整推导链，可用 `bash` 时用 Python/SymPy 精确验算，确认每个条件在哪个环节真正发挥了作用。需要协助时沿用当前任务的分工。
- 若存在真实学生作答或错选，顺着实际步骤定位受阻处；后台纯备课或尚无作答时，不编造学生错因。

## 2. 拆穿题目的构造与设障机制

挑选最能看透本质的维度连贯剖析：
- **每个条件的真实使命**：指明该条件是在**保证存在性/唯一性**、**限定可行域与方向边界**、**提供转化桥梁**，还是仅仅为了**简化计算或包装情境**（可用“如果删掉或改动这个条件，推演会在哪一步失效”直观说明）。
- **破题信号与嵌套层次**：点明题面哪个特征暴露了底层模型，命题人在基础原理之上嵌套了哪几步变形，以及为什么会想到这条路径。
- **小问递进与干扰项设计**：分析前问如何为后问铺路（或后问移除了前问的什么特殊条件）；指出漏检前提或方向失察会如何落入典型歧路。
- **评估备课与训练价值**：判断这道题适合作为概念引入题、承载多种解法比较的主例题、单条件边界变式，还是仅靠繁琐计算拉区分度的偏题，供备课选例与时间取舍使用。

## 3. 变式改题与草案/落盘交付

- **先验算后交付**：需要改编条件或构造反例时，先明确改动意图（强化哪个信号或暴露哪个漏检前提），完整解出新题确认自洽，再交付独立题面与配套教师参考。
- **按角色职责沉淀**：由主老师或整理会话将核实后的条件剖析与变式写入卡片 `## 参考理解` 或备课本 `<details data-notara="teacher">`（学生自己看穿的结构洞察才记入 `## 学生理解`），并回读确认；工作员则将完整草案连同验算依据直接返回发起者。若拆穿了此前个人模板未收录的典型漏检项，可由有写入权限的会话补充进对应 `模板/<名称>模板.md`。

- 需要保存卡片关系时由有写权限的会话按 `notara-pdf-learning-set` 与卡片模板办理；题目分析不直接产生个人联系或复习结果。
