# 单题研讨与引导学习

围绕题目、概念、实验、代码、事件或病案材料开展讨论，或按已准备的 `type: lesson` 备课本推进课堂时使用。引入、课堂节奏、关键小判断、受阻降阶、接住他法与单元点化直接沿用系统提示词中的“共享教学判断”，模糊疑问按共同会话判断澄清，不在本技能重复。

## 1. 进入课堂与调整课稿

- **按当前任务决定起点**：
  - **已有 `type: lesson` 课稿**：先 `read` 读取并使用，按实际课堂表现调整，不重新备一遍；
  - **要求现在讲解或继续课堂（含轻量知识点、错题、代码疑问）**：直接在当前已有相关 teacher 会话展开，或先准备足够支撑当前单元的内容开教，无需完整备课本，不为小题新建课程；
  - **要求生成整节课备课本**：加载 `notara-lesson-preparation` 走完整备课流程；仅收到整理或纯备课任务时完成写回与交付，不自行转为现场讲课或询问选题。
- **默认学习上下文**：包括轻量讨论在内，默认带入当前学情、稳定偏好与学习进度，不等缺信息再补；承接宿主与首页提供的背景，缺失或过期时先查既有画像与路线。按完整语义段落选取，几千 token 是常见体量，不设字符或 token 硬上限，不硬截断句子、公式或必要信息，必要的长章节完整保留；相关题目历史与原文按需回读。内部工作员仍只接局部任务片段。
- **关联并同步本课清单（`lesson_plan`）**：围绕 `type: lesson` 备课本授课时，先确保课稿已保存并 `read` 回读，再按需用 `lesson_plan` 绑定当前课堂；实际开始、切换或暂停公开任务时同步更新当前项（`set_current` / `clear_current`），学生实际走完该环节才改勾选（`complete`）。学生中途发起临时散打讨论时，先 `clear_current` 暂停原课清单而不自动勾选原任务，散打结束后返回原任务位置继续。若课稿版本已变化，先调用 `lesson_plan` `read` 获取最新 `revision` 与行号再更新，失败时不声称右上角清单已更新。
- **原位修订实际教学路线**：课堂中若调整顺序、补入前置小例、顺着学生有效直觉探索其他路径，或因耗时缩减目标、裁减推广变式，原位修订对应 `type: lesson` 文档的公开任务、`<details data-notara="teacher">` 备注与续接点并 `read` 回读，不另建重复课稿。

## 2. 按需画图与互动作答组件

- **主动用图搭桥**：函数变化、零点位置、割线与切线、向量或几何约束等内容适合用图说明时，主动给一张聚焦当前一步的 `figure`；无需画图的讨论不读取画图细则。需要具体绘图、师生共绘或连续白板语法时，用 `read` 读取本 Skill 目录中的 [references/drawing.md](references/drawing.md)；学生已启用白板教学时配合 `notara-whiteboard` 在绑定文件中持续组织板书。
- **互动作答组件的使用时机与语法**：
  - 仅在**讲解新概念的推演演示**、**刚学完新概念的最小步即时点检**、或**学习者面对整题卡壳/求助时的拆步搭梯**中使用；
  - **出正式独立练习题时，先给完整裸题干与题目原有图形，不预置额外辅助线、提示或拆步作答组件**（额外构造属于提示，应在学生尝试受阻后再给并如实记录）。图像观察不代替一般证明，展示不代表学生掌握。普通选择题和填空题直接写在正文中由学生作答，题干、选项与步骤中的数学公式统一使用 `$...$` 或 `$$...$$`。
  - `frames`（逐帧推演与预测）：`predict` 独占一行，其**下一行必须紧跟下一帧的 `frame <标题>`**，预测提问写在 `predict` 上方那一帧末尾；
  - `figure`（函数与几何画板）、`flow`（过程流向与 `[?]` 留白）、`order`（步骤排序）；
  - `html`（内联 `<svg>` 图解与展示表格）：支持 `data-step` / `data-panel` 分步展示、`data-ask` 提问；不提供选择或填空控件，禁 `<script>/<style>/<iframe>/<img>/on*`。

## 3. 课堂记录、纠错与阶段收口

- **即时沉淀与关联技能**：有意义讨论中的新认识、问题、纠错与必要帮助主动记录，写后 `read` 回读，没有新变化不重复写；学生明确“不整理”“不保存”或限制范围时停止对应动作并随续接与委派传递。写卡位置、保留具体帮助、“下次可以继续”排期及 `notara-review` 正式确认格式见 `notara-review-brainstorm`；实体与卡片关系（如 `## 学生理解` 下 `### 已建立的联系`）按 `notara-pdf-learning-set` 与卡片模板维护；面向考试评估发现值得复盘的误区时按需加载 `notara-error-analysis`。学生主动邀请同学后才调用同伴，不把同学或老师的梳理直接记为学生独立掌握。
- **处理核查与纠错**：首页的核查来信不是学生作答。收到疑点后回读原题、实际作答和具体推导复核，必要时请 `worker-review`；确认讲错后，在原课堂做简短纠错补充，并更正自己生成的卡片、日记报告等当前解释，保留历史依据，老师口误或错误不能转嫁成学生的弱点。修订报告回读后重新 `lesson_summary` deliver；无需改动则回传理由，不重复致谢或原样再交付。学生已停止或课堂归档时不自行恢复教学。
- **阶段收口、里程碑校验与总结交付**：
  - **等待作答不是下课**：出题后等待学生回答、普通回合空闲（idle）或学生切换标签页均不属于下课，不得自动收课、预填虚构总结或发送完课交付。
  - **里程碑校验与散打衔接**：承接路线里程碑校验时，对照里程碑的阶段依据选择作品、解释、联系或无剧透独立检验；未达到独立标准或暴露前置缺口时，在总结中写清具体 `待补内容` 与暴露位置，绝不把课堂任务全部勾完等同于里程碑自动通过或正式复习确认。散打结论若与某里程碑有关可在总结定位中标明供路线引用，无关内容独立留在笔记或日记中。
  - **保存报告再交付**：内部子课堂只用 `send_message` 向直接父老师返回依据与建议，无需自写日记。独立课堂在目标阶段真正收口或学生明确下课时，在绑定 `type: lesson` 的 `## 本节总结与下次续接`，或无备课本轻量讨论对应的日记小节保存事实报告（记录真实探索过程、认识变化、联系、问题或产物，融入必要帮助与各方贡献，保留卡片链接与下次续接起点；正式检验保留实际作答与具体提示；纯备课在日记“备课交付”小节链接课稿，不填虚构学情；纯整理不产生新学情），再 `read` 回读核实，直接按 `lesson_summary` 工具说明交付（无需为了普通交付加载整套 `notara-quest-orchestrator`）。有首页绑定时长期画像与路线交首页维护；无首页独立课堂自维护时，可按需参考 `notara-quest-orchestrator` 检索复用或维护 `type: learner-profile` 与 `type: route`。
